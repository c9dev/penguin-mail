# Penguin Mail

Terms the code and its docs use for Gmail mail. The `domain` crate holds the code for each.

## Glossary

**System label**: a label Gmail defines, with the same id in every account, such as `INBOX`, `SPAM`, `UNREAD`, and the category labels. `mailrs_gmail::labels` names them and maps each to a role, a keyword or a category; only the Google adapter and the Gmail fake read them. _Avoid_: system folder.

**User label**: a label the account owner made, with an id like `Label_12` that only that account knows. _Avoid_: custom label, tag.

**Category label**: one of Gmail's `CATEGORY_*` labels, which Gmail puts on inbox mail to sort it. The store keeps each as a category under the same name (`mailrs_domain::category::SOCIAL` and the rest), since Gmail is the only provider with categories. _Avoid_: tab, category.

**Category**: a slice of the inbox that Penguin Mail shows: All, Primary, Updates, Promotions, or Social. Each one is defined by the category labels a thread has or lacks. Primary is mail with no category label but Personal, and Social includes Forums. _Avoid_: tab, inbox type.

**Folder**: Archive, Junk, Trash, or All Mail. Archive is the received mail outside the inbox, which Gmail has no label for. The local store does not keep this mail, so the app lists a folder with a query tree, which Gmail receives as a search, and checks a message's labels to see if it still belongs there. _Avoid_: mailbox, spam folder.

**Target**: what a mail action applies to: a thread, or one message of it when the list shows messages instead of conversations. `mailrs_domain::Target`. _Avoid_: selection, item.

**Reach**: what a button or key pressed in one conversation view acts on: its targets, what they carry (unread, flagged, muted), and the mailbox they were picked from. In the main window several selected rows win over the open conversation; a conversation in a window of its own reaches only itself, in the mailbox it was opened from. `ui::window::reach::Reach`, built by `MainWindow::reach(view)`. _Avoid_: scope, selection.

**Message menu**: the menu a right click, the Menu key or Shift+F10 opens inside one message of an open conversation, every item of which changes that message alone rather than the thread around it: reply, archive, trash, mark, flag, label, export, copy the sender's address. `ui::window::message_menu::groups` decides which items a message gets from its own marks and the mailbox on screen, leaving out what would do nothing there; each item is a `win.message-*` action carrying the message id, so the change goes on the undo stack like any other. The page asks for it through the `mailrs:menu/` link the conversation view intercepts. It differs from a Reach, which is what the header buttons act on. _Avoid_: context menu, popup menu, per-message actions.

**Shortcut**: one line of the Keyboard Shortcuts dialog and the keys behind it, each naming the action it activates and the windows it works in: the main window, a conversation in a window of its own, both, or the composer. `ui::window::shortcuts::SHORTCUTS` builds both windows' key controllers and the dialog, so a key cannot work without the dialog listing it. A letter key, such as `e` or `#`, works only in the main window and gives way while you type in a text field. _Avoid_: accelerator, hotkey, keybinding.

**Mail action**: a change a person or the assistant makes to targets, such as archive, flag in a colour, remind at a time, or label by name. `mailrs_sync::MailActions` runs each one for the window and the assistant alike, carries on past a failed target, and reports each failure in its `Outcome`. _Avoid_: command, operation.

**Muted**: a thread carrying the `$muted` keyword, which Gmail keeps as its `MUTE` label. Gmail's own filters archive whatever arrives on such a thread, so a reply lands outside the inbox without the app doing anything; muting is therefore the label plus one archive, and unmuting drops the label and puts the thread back. `mailrs_sync::TriageAction::Mute`, behind `MailAction::Mute`. The Muted mailbox lists these threads and a row marks them. _Avoid_: ignore, silence, snooze.

**Undo**: the stack of recorded mail actions that Ctrl+Z or a toast's Undo button reverses, newest first. Each press takes one off and reverses what that action changed on each message, taking off what each message gained and putting back what it lost, as the change set reported it, so a message it found already read or archived stays that way. It also puts back earlier flag colours, earlier reminders, and dismissed follow-ups, and the toast names what it took back, a label or folder by the name the person gave it rather than the server's id. The stack holds twenty actions and lasts as long as the run: mail actions are already applied at Gmail, so one that outlived the process would offer to reverse what the server has long since moved on from. A target that has left the folder the action put it in is left there, which is why undoing an archive cannot pull a conversation back out of the trash; erased mail and a signed-out account take their entries with them. The window and the assistant share it. _Avoid_: history, revert.

**Aftermath**: what a mail action leaves stale in the window once it has run: rows to take out at once, a Gmail folder to prune or search again, the counts, the flag colour on open conversations, the Remind Me and Follow Up lists. `ui::window::aftermath::Aftermath::of` decides it from the cause (an action, an undo, or erasing) and the mailbox on screen, and `MainWindow::after_mail` carries it out for the window's buttons, Undo, Delete Forever, the assistant and the notification buttons alike. When an action takes mail out of the list, the window moves on before Gmail answers, by the one rule in `aftermath::leaves` and `MainWindow::move_on`: the next row opens, the conversation pane hides when no row is left, and a conversation in a window of its own closes. It differs from a settings change's effect and from the open thread's stale, which cover other causes. _Avoid_: refresh, side effect, effect.

**Press**: one use of a mail button, a key, a menu item or a drop on a sidebar mailbox, and the plan it comes to: the targets, the mail action and whether Undo keeps it, whether the window moves on first, the question before erasing, the toast's words, or what Delete calls off in Send Later and the Outbox. `ui::window::press::plan` reads the reach, the mailbox and whether the press covers what is shown, rows carried by a drag, or one message, and `press::carry_out` makes the plan happen through `PressEffects`, which the window stands behind and the tests fake. `press::trash_words` words the Delete button from the same table in each mailbox. _Avoid_: click, command, handler.

**Mailbox**: one choice in the sidebar, and what the thread list then shows: a standard mailbox in one account or across all, a person's label, a mail set with no row of its own that the assistant asks for by name, a folder, a search, a smart mailbox, a flag colour, VIP mail, Follow Up, Remind Me, Send Later, or the Outbox. `mailrs_sync::Mailbox`. _Avoid_: view, source, box.

**Standard mailbox**: Inbox, Flagged, Sent, Drafts or Muted, the five mailboxes the sidebar shows for all accounts together and for each one. `mailrs_sync::mailbox::Standard`; each lists one mail set: the inbox role, the `$flagged` keyword, the sent role, the drafts role, the `$muted` keyword. _Avoid_: system label, special folder.

**Queued message**: a message waiting to go out, kept on this computer with the bytes it will be sent from, what the composer needs to reopen it, the tries already behind it, and the time of the next one. `mailrs_store::outbox::Queued`, sent by `mailrs_sync::Outbox`. One table holds both kinds, because both are a message waiting: a Send Later message, whose hour has not come and whose bytes Gmail holds as a draft, and one that hit a problem on the way out. The recorded problem is what tells the two apart and decides which mailbox lists the message. Whoever sends one first takes it with `mailrs_store::outbox::claim`, so the Outbox window's Send Now and the pass that sends what is due never both send it; a claim lapses after ten minutes, for a run that died mid-send. A message tried before is looked for in Sent by its `Message-ID` before it goes again, since the try whose answer was lost may have reached Gmail. _Avoid_: pending message, spool entry, draft.

**Outbox**: the mailbox listing the queued messages with a problem against them, each row saying why the message has not gone and when the next try is. It stays in the sidebar when empty, so a person can look before anything goes wrong. The wait between tries doubles from half a minute to half an hour, the network coming back cuts it short, and after about a day of tries the outbox stops and leaves the message to the person, as it does at once for a failure nothing would fix. A message inside its Undo Send window is not here yet, since nothing is stored until that delay runs out. _Avoid_: queue, spool, pending.

**Mailbox on screen**: the mailbox the main window lists, the one a search goes back to when it closes, the inbox category, and the list feed that loads its rows. `ui::window::on_screen::OnScreen`. The sidebar, the search bar, a notification, a deleted label and a settings change each make one transition on it, and every transition answers with a `Redraw` naming what it left stale, such as the selection, the title, the buttons that hang on the mailbox, and a first page to list, which `MainWindow::redraw` carries out. A conversation in a window of its own keeps the mailbox it was opened from instead. _Avoid_: current mailbox, view state, navigation.

**Smart mailbox**: conditions saved in Preferences that become a query tree, such as "from Ann" and "newer than 7 days". Gmail receives the tree as a search. `mailrs_domain::SmartMailbox`. _Avoid_: saved search, filter.

**Listing**: one page of a mailbox, with its rows, its unread count, the title and subtitle the header shows, and what an empty list should say. `mailrs_sync::Mailboxes` produces it for the window and the assistant alike, so only it knows which mailboxes the store answers and which Gmail does. _Avoid_: result, page, query.

**View**: the settings that change what a mailbox lists: conversation grouping, the inbox category on screen, whether Follow Up is on, the clock, and a row limit. `mailrs_sync::View`. _Avoid_: options, config, filter.

**List feed**: what the thread list loads next, and which answers to that loading still count. It hands out the first page of the mailbox on screen, the next page once the reader scrolls to the end, and one refresh for a burst of change events, which re-reads the named threads, lists the mailbox again, or prunes a folder. `mailrs::ui::list_feed::ListFeed`. Every answer passes through it on its way to the window, and it drops the ones for a mailbox that has since left the screen. _Avoid_: loader, pager, generation.

**Settings change**: one named change to the preferences, such as the text size, an account's signature, or a VIP. `mailrs::settings::Change`. Preferences, the keyboard shortcuts, and the assistant all make the same change the same way, so the same input lands the same way whichever one asks. _Avoid_: patch, setting update.

**Effect**: the part of the window a settings change leaves stale: the list's shape, the sidebar's accounts, row colours, a smart mailbox's conditions, the VIP marks, Follow Up, the inbox categories, the assistant's connection and model, the text size, or light and dark. `mailrs::settings::Effect`. Applying a change reports its effects, the window redoes one part per effect, and a change with no effects saves the file and stops. The effects also carry what a change asks of the address books, read through `Effects::address_books`: switching an account's contacts on reads them, and switching them off deletes that account's, whichever caller made the change. _Avoid_: signal, notification.

**Account settings**: what Gmail keeps for one account and Penguin Mail changes: the automatic reply, the rules, blocked senders, and hidden addresses. `mailrs_sync::AccountSettings` makes each change for the dialogs and the assistant alike. Preferences, which live in the app's own settings file, are something else. _Avoid_: preferences, options, Gmail config.

**Automatic reply**: what Gmail sends back while the account owner is away, with the days it runs between. `mailrs_sync::AutomaticReply` names the first and last day; Gmail stores an end it stops before, and only `AccountSettings` converts between the two. _Avoid_: vacation, out of office, auto-responder.

**Rule**: one server rule: which mail it matches, and the mail sets it adds that mail to or takes it out of as it arrives (out of the inbox role skips the inbox, out of unread marks it read, into the trash role deletes). `mailrs_domain::Filter`; for Gmail each is a Gmail filter, and `mailrs_gmail::model::GmailFilter` holds Gmail's label ids on the wire. The Rules dialog, Block Sender, Categorize Sender, and Hide My Email all make rules. _Avoid_: filter (except for Gmail's own), automation.

**Hidden address**: one plus address from Hide My Email, such as `dana+kite.fern482@gmail.com`, with the rules behind it. One rule gives its mail the Hide My Email label; a second trashes that mail while the address is off. `mailrs_sync::HiddenAddress` holds the address, its note and the two rule ids; `AccountSettings` makes one and changes it, and the app keeps the list in its settings file. _Avoid_: masked address, burner.

**Built-in client**: the Google OAuth client compiled into a release build from `PENGUIN_MAIL_GOOGLE_CLIENT_ID` and `PENGUIN_MAIL_GOOGLE_CLIENT_SECRET`. Every new sign-in uses it. `mailrs_gmail::built_in_client`, recorded as `SignInClient::BuiltIn`. _Avoid_: app key, default client.

**Own client**: a Google OAuth client a person made in their own Google Cloud project and pasted into the old setup page, kept in `config.toml`. Accounts added that way keep it until they sign in again. `SignInClient::Own`. _Avoid_: custom client, user client.

**Settings permission**: the Gmail access an account grants so Penguin Mail may read and change its account settings, asked for at sign-in along with every other scope in one consent. A person may leave it unticked; without it every `AccountSettings` call answers `Permitted::NeedsPermission`, and the caller offers Grant Access rather than showing an error. _Avoid_: scope, consent.

**Delete permission**: the Gmail access an account grants so Penguin Mail may erase mail, asked for at sign-in along with every other scope. A person may leave it unticked, and until it is granted `MailActions::erase` answers `Permitted::NeedsPermission` and changes nothing. _Avoid_: scope, full access.

**Permission prompt**: the Grant Access question that follows every `Permitted::NeedsPermission`, in the window or from an assistant tool, whether the scope was never asked for or the person unticked it on Google's screen. `mailrs::permission::Permission` names the settings, delete, contacts, contact change or calendar permission, and its table holds each one's heading and body; sign-in asks for every scope in one consent, so nothing here picks scopes one at a time. The `Occasion` sets how often it asks: `Needed` when something stopped for want of the permission, each time; `Offer` when something worked without it and the permission would have done more, once per account a run. `MainWindow::ask_permission` shows it and runs consent on a yes. _Avoid_: consent dialog, access request.

**Tool call**: one thing the assistant asks the app to do, by name and with JSON: list a mailbox, organize mail, change a setting. Each mail tool is one entry in `mailrs::assistant::run::catalog`: its name, the label the pane shows, its JSON Schema, and its handler in `mailrs::assistant::run`, which either answers at once or plans a change and names the question to ask before making it. The mail tools reach the model as the source `mail`, beside web search, MCP servers and skills. The tools change mail through the same `MailActions` and `AccountSettings` the window uses, so the assistant cannot do anything the user could not. _Avoid_: function call, command, action.

**MCP server**: a program or web service the owner adds on the AI page to give the assistant more tools. `mailrs::assistant::sources::mcp` offers each enabled one as the source `mcp:<name>`, with its tools named `<name>__<tool>`, and `mailrs_ai::mcp::McpClient` speaks the protocol to it. The registry there starts a server on the first turn that needs it, keeps it for later turns, and stops it when the settings drop it or the app quits. _Avoid_: plugin, connector, extension.

**AI feature**: something in the app that sends words to a model: the assistant and translation today. `mailrs::settings::Feature`, one row each under Used For on the AI page. Each one uses a model of its own or follows the assistant's, and `mailrs::assistant::model_for` is the one way to a model, so every caller names the feature it is working for. _Avoid_: AI function, capability, skill.

**Connection**: a place a model runs, set up once on the AI page: a local server with OpenAI's API, the Anthropic API, or a Claude subscription through Claude Code. `mailrs::settings::AiProvider`, whose `Off` stands for none. Addresses and commands live in the settings and keys in the keyring, so two features on one connection share them. _Avoid_: provider (in wording the user reads), backend, endpoint.

**Search engine**: where a local model's `web_search` sends its query: the Brave Search API with a key from the keyring, or a SearXNG server asked for JSON. `mailrs::assistant::sources::web::SearchEngine`, chosen under Web Search on the AI page. Claude never uses one: through the API or Claude Code it searches with Anthropic's own tools, and the web source offers it nothing, so it never sees two searches. _Avoid_: engine (which names gpg and gpgsm), search provider.
**Turn**: one question to the assistant and everything the model did to answer it, in the order it arrived: what it thought, each tool call with its input and result, and the reply. `mailrs::assistant::turn::Turn` takes the model's events and says which step each one changed, and the pane draws a folded row per thinking step and tool call. While the turn runs its phase says what the model is doing now: waiting for the model, thinking, running a tool, waiting for the person to allow one, or writing. _Avoid_: exchange, message, round (which is one request to the model, and a turn can take several).

**Chat history**: what a chat sends back to the model each round: the turns so far, oldest first, and the one under way. `mailrs_ai`'s `history::History`, which the Anthropic and local-server providers both render. A turn that fails or that Stop cut short is taken back whole, question and all, and old turns leave the front whole when the chat outgrows its budget, so the model never reads a tool result without the call it answers. It also names where the cache breakpoint goes, on the latest message from the user's side. _Avoid_: context, transcript, conversation (which is the whole chat object).

**Skill**: a folder of instructions for one kind of task, with a `SKILL.md` whose front matter gives a name and a description, found in Penguin Mail's skills folder or Claude Code's. `mailrs::assistant::sources::skills::Skill`, whose id is where it came from and its folder's name, such as `claude-code/pdf`. Each is off until the person turns it on; the system prompt lists the ones that are on, and the model reads the rest with `use_skill`. _Avoid_: plugin, extension, AI feature (which is something in the app that sends words to a model).

**Sandbox**: where a skill's commands run: bubblewrap with the system's programs read-only, the skill's folder at `/skill`, a scratch folder at `/work` that lasts as long as the chat, no home folder, and no network unless the skill is allowed one. `mailrs::assistant::sources::skills::sandbox`. The shell source asks the person before each command. _Avoid_: container, jail (in wording the user reads), VM.

**Desk**: the port a module reads the window through. The assistant's tools read the preferences, the accounts and their labels, the view, and what is on screen, meaning the mailbox, the open conversation, and the selected rows: `mailrs::assistant::run::Desk`. The engine run reads which engines this computer has, the protected messages it claims, and whether that thread is still on screen: `mailrs::protection::run::Desk`. The thread run reads the conversation on screen, the reader's settings that shape it, and what the page draws for a translation: `mailrs::open_thread::run::Desk`. Every method gives back plain data, so a test fills one in without a widget. _Avoid_: context, state, session.

**Effect port**: the port a module changes the window through. The assistant's tools approve, open, compose, send, copy, ask for the settings permission, and the rest: `mailrs::assistant::run::Effects`. The engine run fetches the message as it was sent, asks gpg or gpgsm about it, and puts the answer above it: `mailrs::protection::run::Effects`. The thread run reads the store and Gmail for the thread, its bodies, pictures, invitation and flag colour, asks the model for a translation, and makes the named changes on the conversation view: `mailrs::open_thread::run::Effects`. The window is one adapter behind each and the tests are another, so all three run with no GTK. Not to be confused with a settings `Effect`, which names a part of the window a preference left stale. _Avoid_: side effect, callback, handler.

**In-memory Gmail**: `mailrs_sync::fake::FakeGmail`, one account's mailbox held in memory behind the same `GmailApi` seam as the real client. It answers Gmail's search language, keeps a history log, and takes writes. It also holds the account's calendars and their events, answering the calendar list, a calendar's change feed and its writes the way the real Calendar API does, with a log of what changed for a test to read directly. A test can withhold an OAuth scope so calls that need it answer `MissingScope`, switch the Calendar API off, and pin the clock `newer_than` counts from. Sync's tests, the assistant's tool tests, and `penguin-mail --demo` all run on it, so there is one fake to keep honest rather than two; sync ships it under the `fake` feature so only the app and the tests carry it. `mailrs_sync::fake::fill_store` fills a new account's store from it through sync's own bootstrap and backfill, which is how the demo and the assistant's tests get their mail into the store. _Avoid_: mock, stub, demo API.

**Rich body**: the composer's message while it is being written as rich text: lines with a kind, each carrying runs of styled words. `mailrs::richtext::RichBody`. It becomes the HTML part of the message, the plain text part beside it, and the Markdown a writer who prefers marks sees, and it reads Markdown back in, which is how a reply's quote and the assistant's drafts arrive. _Avoid_: document, rich text, formatted body.

**Send gate**: what stands between a finished message and sending it, one check at a time: a message that cannot go is refused, then a message meant to go out encrypted that cannot be is asked about, then a promised file that is missing. `mailrs::compose::gate` names the next step, and the composer asks what it says to ask until it says send. _Avoid_: send checks, validation, preflight.

**Foreground work**: a Gmail call the user is waiting on: a mail action, opening a thread, listing a folder, and whatever the assistant runs on their behalf. It takes the account's quota ahead of background work and waits out a rate limit rather than failing. `mailrs_sync::Priority::Foreground`, which is what work is unless some caller wrapped it in `mailrs_sync::background`; the Google adapter hands the same priority to Gmail's quota bucket. _Avoid_: user action (too narrow, the assistant counts too), interactive.

**Background work**: a Gmail call nobody is waiting on: backfill, history polling, pruning, the inbox check. The sync engine runs its whole tick as background work, which leaves 100 of the account's 250 unit burst for the user and stands aside while a foreground call waits. `mailrs_sync::Priority::Background`, which the Google adapter passes on to Gmail's pacing. _Avoid_: sync work, low priority.

**Whole thread**: a thread the store holds every message of, as a fetch of the thread leaves it. The window keeps messages by date, so a thread in it can lack its older replies; opening a thread trusts the store without asking Gmail only when the thread is whole and a history replay ran in the last 75 seconds. History keeps a whole thread whole, and a new bootstrap's sweep clears the mark on the threads it trims. `threads.whole`, set by the change set's `MarkWhole`. _Avoid_: complete thread, full thread.

**Base subject**: a subject with its reply and forward prefixes, mailing-list tags, and extra spaces gone, in lower case, so "Re: [team] Fwd: Lunch" and "Lunch" agree. `mailrs_domain::subject::base`, alongside `subject::replies`, which says whether a subject carried a reply or forward prefix at all. Local threading is the only reader. _Avoid_: normalised subject, subject key.

**Local threading**: threading done by the store for a server that keeps no threads: a copy of a stored message, or a reply that arrived first, shares its thread; then the nearest message the References and In-Reply-To headers name; then, for a subject with a reply prefix, the nearest message with the same base subject within 30 days. Otherwise the message starts a thread named by its own id. `mailrs_store::threading`, reached through `Change::UpsertLocal`. Gmail supplies its own threads and never runs it. _Avoid_: conversation grouping (the view's setting).

**Inbox check**: the sync engine's comparison of the store's inbox with Gmail's, once when an account starts and then every hour with pruning. It lists Gmail's inbox, and for each stored message whose place in the inbox disagrees it fetches the message again or, when Gmail no longer has it, deletes it. History replay applies each change once, so this is what corrects a message some older write left wrong. `AccountSync::reconcile_inbox`. It waits for the window to finish loading and leaves mail the store has never seen to history, which announces new mail. _Avoid_: full sync, resync, refresh.

**Quota bucket**: the tokens one account may spend at Gmail, refilled at 200 units a second up to a 250 unit burst, under Gmail's own 250 a second. `mailrs_gmail::AccountQuota`, one per address in the OAuth client's `QuotaPool`, plus a project bucket every account waits on. Every call spends from it before it goes out, so batching and pacing show up here rather than in a 429. Only the Google adapter, `mailrs_sync::services::Google`, reaches it; the engine and the window say foreground or background and nothing more. The Google adapter also owns Gmail's prices: which of `messages.get` and `threads.get` a fetch uses, and the page sizes of a listing. _Avoid_: rate limiter, throttle.

**Address book**: the contacts one Google account holds, stored on this computer: each person's name, addresses, photo, organization, and phone number. `mailrs_store::address_book` keeps one per account, and `mailrs_sync::ContactBook` reads it from the People API, walking the pages and keeping the sync token so later refreshes cost one call. It stays empty until the owner turns contacts on in Preferences, and turning them off deletes it. _Avoid_: Google Contacts, contacts (which also names the suggestion list).

**Contact**: one person in an address book, with every address Google holds for them, the primary one first. `mailrs_store::address_book::Contact`. _Avoid_: person, entry, card.

**Correspondent**: someone Penguin Mail found by reading stored mail rather than an address book. `mailrs_store::contacts::Correspondent` scores them by how often they come up, weighing someone written to above someone who only wrote. _Avoid_: contact, sender.

**Recipient suggestion**: one row of what the composer offers while an address is typed, and what search offers for a name. `mailrs_store::contacts::Suggestion` merges the address books with the correspondents: a contact comes first whatever the mail says, and mail orders the contacts among themselves. _Avoid_: completion, autocomplete entry.

**Recipient chip**: one address in a composer address field, drawn as a pill with a close button. The chips stay out of the Tab chain; Left from the start of the entry reaches them. `mailrs::ui::composer::recipients`. _Avoid_: tag, token, bubble.

**Roving focus**: a row of controls that is one stop on the Tab chain, with the arrow keys moving between its members and Tab returning to the one last used. The formatting bar works this way; the recipient chips take the same arrow keys and never join the Tab chain. `mailrs::ui::roving`. _Avoid_: focus group, tab group.

**Contacts permission**: the Google access an account grants so Penguin Mail may read its contacts, asked for at sign-in along with every other scope. A person may leave it unticked; without it every `ContactBook` call answers `Permitted::NeedsPermission`, as the settings calls do. _Avoid_: scope, consent.

**Contact change permission**: the Google access an account grants so Penguin Mail may add and change its contacts, asked for at sign-in along with every other scope. Only the assistant's `create_contact` and `update_contact` need it, and they ask again the first time they find it missing; reading contacts needs only the contacts permission. `mailrs::permission::Permission::ChangeContacts`. _Avoid_: write scope, full contacts access.

**Contact card**: what the sender's face or name in a conversation opens: their photo, name, addresses, and organization, with the three things the app already does about a person. `mailrs::ui::contact_card`. A sender in no address book still gets one, built from the message header. _Avoid_: profile, popover, details.
**Invitation**: what one `text/calendar` part of a message says about one event: its title, when it runs, where, who is coming and what each of them said, the organizer, how it repeats, and the UID and sequence that tell one version of an event from the next. `mailrs_domain::invitation::Invitation`. _Avoid_: meeting request, calendar event, ICS.

**Answer**: Yes, No or Maybe. It is what a guest said about an invitation and what the user sends back, so one type covers both. `mailrs_domain::invitation::Answer`. It leaves by whichever of the two roads is open: Google Calendar for an event Google holds, and otherwise a reply. _Avoid_: RSVP, response, PARTSTAT.

**Reply**: the answer as RFC 5546 writes one: a mail to the organizer carrying a `METHOD:REPLY` calendar object with the invitation's UID and sequence, the organizer copied over, and the user as the only attendee. `mailrs_domain::invitation::reply` writes it and `mailrs_sync::invitations` sends it. Nothing but mail takes part, so it reaches an organizer on Exchange, an event Google never filed, and an invitation that arrived at an address the calendar does not belong to. _Avoid_: RSVP email, ICS reply, iTIP message.

**Counter proposal**: asking the organizer for another time, as a `METHOD:COUNTER` object with a new start and end. `mailrs_domain::invitation::counter`, sent the way a reply is. It settles nothing: the event stays where it was until the organizer answers, so the answer buttons stay where they were too. _Avoid_: reschedule, new time request, tentative.

**Scope**: whether an answer or a proposal covers the one occurrence an invitation names or the whole series. `mailrs_domain::invitation::Scope`. An occurrence carries the organizer's own `RECURRENCE-ID` in the reply and points the Google call at that instance; the series carries neither. The card asks only for an invitation that names one occurrence, and every other invitation is a series. _Avoid_: recurrence, range, this and future.

**Clash**: what the user already has on while an invitation's event would run, which the card says in a line: "You have Design crit then." `mailrs_sync::Invitations::busy` reads it from the local copy once the account's calendars are synced, on the ones the account owns, and asks Google only before that, once per invitation at background priority, and only for one still waiting on an answer. An event the user declined, one marked free, a cancelled one and an all-day one leave the hour open. _Avoid_: conflict, overlap, double booking.

**Series**: how a repeating event on the calendar runs: its `RRULE`, and for a rule that stops after a number of occurrences, how many are still to come. `mailrs_gmail::Series`. An invitation to one occurrence carries no rule of its own, so `mailrs_sync::Invitations::series` asks Google for it at background priority and the card shows it in words in the repeat line: "Every Tuesday, 6 left", "Every Monday until 3 March", "Every week, no end date". Without the calendar permission the line stays empty. _Avoid_: recurrence, rule, repeat.

**Invitation change**: what a message does to an event the user already has: it moves it, changes something else about it, or cancels it. `mailrs_sync::invitations::Change`. Only a version with a higher sequence changes anything, and the store keeps what each version changed, so reopening the message says the same thing twice rather than falling silent. Not to be confused with a settings `Change`, which is one named change to the preferences. _Avoid_: update, diff, revision.

**Event card**: the card above the message body that shows an invitation, with Yes, No and Maybe in it, the clash line, Propose New Time, and, for one occurrence of a repeating event, the choice between it and the series. `mailrs::ui::invitation::EventCard`. It says under the buttons where the last answer went, since an answer Google filed shows on the user's own calendar and a mailed reply does not. The message itself goes on being drawn below, so Google's own links keep working for anyone who declines the calendar permission. _Avoid_: banner, widget, preview.

**Calendar permission**: the Google Calendar access an account grants, asked for at sign-in along with every other scope, which lets Penguin Mail mark an answer on the user's own calendar, ask what else the hour holds, and let the assistant read and change events. It also covers the calendar list, so the local copy can read every calendar rather than the primary one alone; an account that granted the older, narrower scope still gets its primary calendar copied, under its own address, until it grants the list too. A person may leave either half unticked. Without it the answer still reaches the organizer as a reply, and the window offers Grant Access once a run rather than at every press; an assistant calendar tool asks each time it finds the permission missing, since it can do nothing without it. _Avoid_: scope, consent.

**Withheld permission**: a scope the person left unticked on Google's consent screen, or that an account added before this scope existed has never been asked for. `mailrs_sync::Withheld`, read from `AccountServices::withheld` and filled from the account's own granted scopes; unknown grants withhold nothing, so an account still starting offers everything until a read says otherwise. A feature that finds its scope withheld turns off and says why, rather than surfacing the refusal as an error. _Avoid_: missing scope.

**Grant banner**: the dismiss-free `adw::Banner` across the top of the window for an account that has never been through a consent asking for every scope, `app/src/permission.rs`'s `wants_banner`. Its Grant Access button is the one place a browser opens for this: `MainWindow::grant_access`, which the calendar sidebar row and the Preferences rows for a withheld account also end at. It never opens at start or from the tray, and one consent ends it, granted or not. _Avoid_: consent banner, permission banner.

**Event**: one entry on any calendar of the account, with its id, title, when it runs, where, and who is coming, in the neutral shape every provider maps onto. `mailrs_domain::calendar::Event`; `mailrs_gmail::Event` is the Google adapter's own shape, read off the wire and mapped to the neutral one before anything else touches it. `mailrs_sync::Calendar` lists, makes, changes and deletes events for the assistant, and tells the guests each time. A time goes in and out of the tools as local time, and an all-day event is named by its first and last day, though Google stores the day after the last. Not to be confused with an invitation, which is what one message says about an event. _Avoid_: appointment, meeting, calendar item.

**Free time**: the stretches inside working hours, 09:00 to 18:00 on weekdays unless the user says otherwise, that no busy event touches. What counts as busy is what counts as a clash: an event declined, marked free, cancelled, or lasting all day leaves the time open, and only a calendar the account owns counts. `mailrs_sync::Calendar::free` reads the local copy once it is synced and asks the provider directly before that; `mailrs_sync::calendar::free_slots` does the arithmetic once the busy stretches are in hand. _Avoid_: availability, gaps, open slots.

**Calendar**: one calendar on an account, as the calendar view lists it: its name, colour, whether the account may write to it, and whether the view shows it. `mailrs_domain::calendar::Calendar`. _Avoid_: agenda, schedule.

**Local copy** (calendar): the account's calendars and events kept in the store and read from there, fresh within a minute while the window is open. `mailrs_sync::calendar_copy::CalendarCopy`, ticked from the app's own timer as the address book is, not from the mail engine's loop; `docs/adr/0001-calendar-local-copy.md` records why. _Avoid_: cache, mirror.

**Calendar scope**: which of an account's calendars an `occurrences` query reads: every one the person has not hidden, every one regardless, or only the ones the account owns, which the clash line and free time use. `mailrs_store::calendar::CalendarScope`. Not to be confused with a mail action's Reach, which is what a button or key acts on. _Avoid_: reach, view.

**Occurrence**: one showing of an event on the grid; a series has one per repeat, expanded for the range on screen. `mailrs_domain::calendar::Occurrence`. Each has an id of its own, `Occurrence::id`, in Google's form: the series id, an underscore and the original start in UTC (`standup_20261022T090000Z`, or `standup_20261022` for a whole day). A change or a delete given that id reaches that occurrence alone, never the series. Not to be confused with `invitation::Occurrence`, the one occurrence an invitation names by the `RECURRENCE-ID` it carries. _Avoid_: instance, recurrence.

**Event block**: the button `TimeGrid` and `AllDayStrip` draw for one placed occurrence: a bar in the calendar's or the event's own colour, the title and the time, dashed while the account has not answered it and struck through once it has declined. `mailrs::ui::calendar::block::EventBlock`. Named apart from "Event card", which is the invitation card a message shows (`mailrs::ui::invitation::EventCard`), so the two never collide in a search or a stack trace. _Avoid_: event card, event cell.

**Change queue**: calendar edits made here that the provider has not taken yet, sent in order; a change the provider turns down leaves the queue and the provider's version stays. `mailrs_store::calendar::QueuedChange`. _Avoid_: outbox (that is mail's).

**Turned down**: a change made here that the provider refused when the queue tried to send it, such as an event changed elsewhere first or a calendar gone read-only; the local copy takes the provider's version in its place. `mailrs_sync::calendar_copy::TurnedDown`. _Avoid_: conflict, rejected change.

**Send-as address**: one address an account may send mail as: its own, or an alias whose owner has confirmed it. Gmail keeps a display name and a signature per address, so choosing one chooses all three. `mailrs_sync::SendAsAddress` is what `IdentityService::identities` reports and `AccountSettings::send_as` hands the app; `mailrs::compose::SendAsAddress` is the copy Preferences keeps, so a composer opens without waiting on the network. An alias Gmail has not verified is left out, since Gmail would refuse to send from it. _Avoid_: alias, from address, sender.

**Identity**: one row of the composer's From list: a send-as address with the account it belongs to, the display name, and the signature that goes with it. `mailrs::compose::Identity`. A reply opens on the identity the mail was written to, a new message on the one that account last sent from. _Avoid_: account, profile, persona.

**Signature**: the text Gmail keeps for one send-as address, which goes below what the person writes. Whoever opens a composer or sends a message says whether it gets one through `mailrs::app::Signature`: `Add` for a message Penguin Mail starts (new, reply, forward, or one the assistant writes), `AsWritten` for one a composer opened before, which added it then (a saved draft, an undone send, a message back from the outbox), and for a request the person never wrote, such as unsubscribe mail. A new message comes from the account Preferences names, else the one on screen, else the first; `App::new_message` applies that rule. _Avoid_: footer, sign-off.

**Prose**: the parts of a draft a dictionary should judge. A quoted reply and a code block are not prose, because the buffer gives those lines their own kind; nor is a list marker, a run of inline code, or a picture, because those carry their own tags; nor is a word with a digit, an underscore, an `@` or a slash in it, because that is an address or an identifier. `mailrs::ui::composer::spell` reads all of this off the buffer rather than the text, so rich text and Markdown answer the same way. _Avoid_: body, content, checkable text.

**Squiggle**: the mark under a misspelling: a `gtk::TextTag` named `misspelled` with Pango's error underline. It lies beside the characters rather than in them, so it shows through bold, a link or a list, and it cannot reach the message: `richbuffer::read` builds the rich body from the block kinds, the four style tags and the link tags, and asks about nothing else. _Avoid_: highlight, underline, marker.

**Notification button**: one of Archive, Mark as Read, Delete and Reply on a new-mail desktop notification. `mailrs::notify::Button`, and Preferences chooses which of the four appear. A daemon that does not advertise the `actions` capability gets a plain notification with none of them, and the body still opens the conversation. The three that change mail go through `MailActions`, so they batch per account and Undo reverses them; Reply opens a composer. _Avoid_: notification action, hint.

**Template**: a saved body the composer drops into a message, with a name and an optional subject. `mailrs_store::templates::Template` keeps it as Markdown, which is what a rich body reads and writes, so an inserted template arrives with its styling. A template follows the person rather than an account, so every account sees the same list. _Avoid_: canned reply, snippet, boilerplate.

**Promise**: a phrase in what the writer typed that says a file is coming, such as "see attached" or "segue em anexo", with the sentence it sits in. `mailrs::attachcheck::promised` finds one in the subject and the body, reading only the writer's own words: the quoted original, the forwarded message and the signature are cut off first, and a link that spells out a phrase does not count. The composer asks before sending a message that makes a promise and carries no file, and Preferences turns the question off. _Avoid_: reminder, warning, attachment hint.

**Placeholder**: a name in double braces that a template fills in as it goes into a message: `{{first_name}}`, `{{name}}` and `{{email}}` from the first recipient, `{{subject}}`, and `{{date}}`. `mailrs::templates::expand` fills them on the way in rather than on the way out, so the saved template still reads `{{first_name}}` the next time; a name it does not know stays as written, since a body may hold braces of its own. _Avoid_: variable, token, merge field.

**Signature**: what the person's gpg made of a signed part: who signed it, whether the text is the text that was signed, and how far the trust database vouches for the signer. `mailrs_pgp::Signature`, which also lists every user id on the signing key with its own validity. The verdict and the trust answer different questions, so a key nobody has vouched for still gives a good signature, and a signature from a key this computer lacks is unchecked rather than bad. _Avoid_: verification result, signature check, validation.

**Canonical part**: the bytes a signature is actually made over: the part with CRLF line endings throughout and anything a mail server might rewrite encoded out of reach, which means whitespace at the end of a line and bytes above ASCII. `mailrs_pgp::mime::canonical` makes it, and the same bytes go into the message, so the two cannot drift apart. _Avoid_: normalized body, cleaned part.

**Inline PGP**: armor written into a `text/plain` body rather than into MIME parts, either an encrypted message or text left readable with its signature underneath. `mailrs_pgp::inline` finds the block among whatever a mail client wrote around it and opens it. RFC 3156 came later and never replaced the habit. _Avoid_: legacy PGP, armored text.

**Recipient key**: what gpg holds for one address a message is going to: a key it would encrypt to, or nothing. `mailrs_pgp::Recipient`. The composer offers encryption when every recipient has one and names the ones that do not; how far each key is trusted belongs in a warning, not in that decision. _Avoid_: public key, certificate, contact key.

**Mark**: what the protection card says about a message: a line naming what happened, a line saying how much it is worth, and which of the three tones the card takes. `mailrs::protection::Mark`, which both engines fill. Good, bad and unchecked stay three answers rather than two, because a signature from a key this computer lacks is not a bad signature. The good tone says who wrote the message, so a good signature earns it only when the key or certificate names the address in From and the person's own trust reaches that address: a vouched OpenPGP user id, or an S/MIME chain to a trusted root. A key nobody vouched for, or one that names somebody other than the sender, gives an unchecked card that says which. `protection::read` is the one place that weighs it. _Avoid_: status, badge, verdict (which is the engine's word for one half of this).

**Protection card**: the card above the message body that shows a mark. `mailrs::ui::pgp::PgpCard`, named for the standard it was built for and since taken over by both. It sits above the event card, has no buttons, and stays put once the engine has answered, so a message that was opened out of its ciphertext goes on saying it arrived encrypted. _Avoid_: banner, badge, security indicator.

**Protection**: the wrapper a message arrived in and the standard that wrote it: `multipart/signed` or `multipart/encrypted` under RFC 3156, and under S/MIME the same `multipart/signed` plus the two blob shapes of `application/pkcs7-mime`. `mailrs_domain::Protection`, which `mailrs_mime::read` reads off the top-level part and only there, since a signed part further down belongs to a message somebody forwarded. Naming the standard is how the app knows which engine opens the message. The signature covers the bytes as they were sent, so whoever checks one fetches the raw message; until then the body holds only the first part of a `multipart/signed`, the one a signature claims to cover. Inline PGP carries no wrapper and is found in the text instead. `mailrs::protection` is the app's side of all this: the mark both engines fill, the MIME they read the same way, and `protection::engine`, which is where a message goes to find out which of the two it needs. `mailrs::pgp` and `mailrs::smime` are the two adapters over it, and neither knows the other. _Avoid_: encryption status, security level.

**Engine finding**: what gpg or gpgsm found in one protected message, in words neither standard owns: whether it arrived encrypted, the signature over it (a verdict, the signer, and how far the person's own trust reaches that signer), and the part the engine checked or opened. `mailrs::protection::Found`, which each adapter fills and `protection::read` alone turns into a mark and a body. That body is always cut from the part the engine checked or opened, so a third part in a `multipart/signed`, or text written around inline armor, never shows under the card. _Avoid_: result, verification result.

**GnuPG runner**: the one way both engines start `gpg` or `gpgsm`: `mailrs_pgp::gnupg::Program::run`. It writes the input while it reads the output, reads the status lines from a pipe of their own rather than from stderr, and takes a `Pinentry` on every run, `Never` for anything that only reads or encrypts and `MayAsk` for decrypting and signing, so no new call can put a window in front of the person by forgetting a flag. `Run::signatures` reads every signature the status lines describe, for either program. _Avoid_: wrapper, gpg helper.

**Remembered verdict**: what the engine said about a signed message that arrived in the clear, kept in memory for the rest of the run so reopening the conversation draws the card without fetching the raw message or starting gpg. `mailrs::protection::remembered::Verdicts`, keyed by message id and held only while the keyring's newest change time stays the one it was read against. Nothing from an encrypted message is kept, and an engine failure is not kept either. _Avoid_: cache (in wording the user reads), stored signature.

**Claim**: the "ask the engine once" mark on one protected message, taken before anything is awaited. An engine run claims every protected message of the thread that has none yet, newest first, and asks about them one at a time. `mailrs::protection::run::Claimed` is one message with that mark already set, so holding one says no second pinentry can open for it while this run lasts. A message whose engine this computer lacks is left unclaimed and reads on the day that engine turns up. _Avoid_: lock, reservation, token.

**Wanted**: the conversation an answer belongs to, and the only way a run reaches its effect port. `mailrs::wanted::Wanted` holds the target the run started on, the account, the thread, and the one message when the view shows one, and hands an answer back while that target is on screen and nothing otherwise, so the question a window task must ask after every await is asked for it: the reader may have opened something else while gpg held a pinentry or Gmail answered, and an answer they are no longer waiting for has nowhere to go. The engine run and the thread run share it. _Avoid_: stale check, guard, cancellation.

**Open thread**: the conversation on screen as plain data: its messages and bodies, which ones the reader opened, what they allowed, and what the engine and the model made of it. `mailrs::open_thread::OpenThread`. It builds the page itself, in `page`: which body each message shows, the cleaned HTML kept for each, and, through `prose`, which message a translation reads. The conversation view loads that page, changes the thread only through named changes, and keeps only what WebKit needs: the content filter and the background colour. The runs read it through their desks. _Avoid_: current thread, selection, model.

**Inline picture**: a picture an HTML body names by `cid:`, which arrived as a part of the same message. `mailrs::open_thread::InlineImage`. Cleaning points each at an address of the app's own `mailrs-cid` scheme, with the account, the message and a version in it, and the conversation view serves the bytes from the open thread; they never go into the page. The pictures arrive after the text, as a step of the thread run, and the page's requests wait for them. An engine that opens a message replaces its pictures under a new version, so WebKit cannot answer from a picture it kept of the old ones. _Avoid_: embedded image, attachment (which the rows below the message list).

**Part path**: where a file sits in a message, as IMAP numbers the parts: "1" for the body of a message that is not multipart, "2" for the second part of a multipart, "1.3" for the third part inside the first. `mailrs_mime::part` cuts a file out of a raw message by it, the Google adapter fetches one file of a large message by it, and the store keeps it as the file's `part_id` and `attachment_id`. _Avoid_: attachment id, part id.

**Raw limit**: the size, 2 MB, under which a message is fetched raw and read whole. A message at or over it, or of unknown size, is fetched as its structure and its text parts, and each file comes alone when someone opens or saves it. `mailrs_sync::RAW_LIMIT`, compared with the size the listing reported (Gmail's `sizeEstimate`). Both paths give the same body and the same part paths. _Avoid_: size cap, threshold.

**Raw cache**: the last small messages an account fetched whole, kept in memory up to 16 MiB per account. `mailrs_sync::raw_cache::RawCache`, which `AccountSync` reads before it asks the server, so a file saved, a picture drawn or a signature checked right after a small message opened costs no second fetch. A message at or over the raw limit never enters it. _Avoid_: message cache (the body cache is on disk and holds text).

**Patch**: the `<article>` elements of the page on screen that a change touched, with their new HTML, which the conversation view puts in place of the old ones instead of loading the page again. `mailrs::open_thread::Page::Patch`. `OpenThread::page` keeps a hash of the head and of each article it last handed out and answers a patch while the head and the list of messages stay the same; a new theme, remote images allowed, or a message joining or leaving the thread loads the whole page. The view holds a patch until WebKit has parsed the latest page, and keeps the first message on screen where it was. _Avoid_: diff, update, partial reload.

**Thread run**: the life of the open thread, from the click to the last card. `mailrs::open_thread::run::ThreadRun` shows the stored copy, fetches the whole thread and its bodies, marks it read after the delay, fetches the pictures for the attachment rows, reads the invitation and what clashes with it, offers and makes a translation, starts the engine run, and refreshes the thread when the store changes under it. _Avoid_: loader, controller, thread manager.

**Stale**: what an event on the open thread leaves out of date: the translation card, the engine run's claim, the event card, the inline pictures, the pictures on the attachment rows, the unread mark. `mailrs::open_thread::run::Stale::after` names them for each event, so a new body brings every card up to date and a decrypted one rereads its invitation and language without asking the engine again. The page and the header buttons are not in it, because each named change on the view redraws what it touched. _Avoid_: dirty flags, invalidation.

**Certificate**: what gpgsm holds for one address: the subject it names, the address on it, and its fingerprint. `mailrs_smime::Certificate`. Only one whose chain reaches a root in the person's trust list counts for encryption, because gpgsm files away every certificate a signature carries when it checks that signature, and a certificate a stranger mailed in would otherwise take the next message meant for the address it names. The composer offers encryption when every recipient has such a certificate and names the ones who do not. _Avoid_: key, public key, cert.

**Chain**: how far the line of certificates behind a signature got: to a root in the person's own trust list, or not that far. `mailrs_smime::Chain`. It answers who the signer is, which is a different question from whether the text is the text that was signed, and a corporate certificate from an authority this computer has never been told about gives a good signature with an untrusted chain. A chain can also reach a trusted root with its revocation unknown: gpgsm could not learn from the certificate authority, within ten seconds, whether a certificate on it was revoked. The card then names the signer in the neutral tone and says the revocation went unchecked. _Avoid_: trust, validation, path.

**Revocation check**: gpgsm asking dirmngr, and dirmngr asking the certificate authority's server for its CRL, whether a certificate on a chain was taken back. `mailrs_smime::Smime::verify` gives it ten seconds, then kills that gpgsm run and checks the signature again without it, so an offline computer or a slow authority never keeps a message closed. _Avoid_: CRL check (in wording the user reads), OCSP, validity check.

**Standard**: which of the two, OpenPGP or S/MIME, signs or encrypts a message on the way out. `mailrs::protection::Standard`, which the composer sets on the draft: the recipients decide it for an encrypted message and the sender's own key or certificate for one that is only signed. OpenPGP wins when both could carry it, so that nothing about a message the app already knew how to send changes the day gpgsm turns up. _Avoid_: scheme, protocol, format.

**Hidden recipient**: a reader of an encrypted message whose key id gpg leaves out of it (`--hidden-recipient`), so the others can tell somebody else holds a key to it and not who. It is how a Bcc stays blind under OpenPGP. `mailrs_pgp::Readers::hidden`, which `mailrs::protection::Addressees` fills from the draft's Bcc, less anyone To, Cc or From names anyway. S/MIME has no such thing, since CMS names every recipient inside the envelope, so the composer will not encrypt a draft with a Bcc under S/MIME. _Avoid_: anonymous recipient, throw-keyids.

**Encrypted draft**: a draft whose message is meant to go out encrypted, which Gmail keeps with its headers readable and its body encrypted to the writer's own key or certificate alone, marked `X-Penguin-Mail-Draft: encrypt` (`; sign` when Sign was on). `mailrs::protection::draft` writes it when the composer or the assistant's `edit_draft` saves (`save`), and opens it again when the window's Edit or `edit_draft` reopens it (`reopened`), with a pinentry if the engine wants one. The recipients' keys play no part until the message is sent. _Avoid_: secret draft, sealed draft.

**Find bar**: the bar Ctrl+F puts over an open conversation, holding the query, the count of matches, and an arrow each way. `mailrs::ui::find::FindBar` asks WebKit's own `FindController` for the text and counts the steps itself, since WebKit reports how many matches a page holds but never which one it highlighted. A query in lower case matches either case and a capital asks for that capital. Every message of the thread opens while the bar is up, because the stylesheet hides a closed message's body and WebKit finds nothing there. _Avoid_: search bar, which is the mailbox search, filter.

**Translation**: one message's prose in the language the interface is in, made by the model chosen for translation when the reader asks for it. `mailrs::translation` counts the commonest words of a handful of languages to tell what the message is in, cuts the prose out of the body the page draws, sends the pieces and nothing else, and puts each one back where it came from, so a bank statement stays the table the bank wrote. It lasts as long as the thread stays open and never reaches the store, because it is text a model derived and tomorrow's model would write it differently. Nothing is sent until the button is pressed: with a local server the words stay on this computer and with Anthropic or a Claude subscription they do not, and the card says which before anything goes out. _Avoid_: machine translation, localization (which is the interface's own words, in `mailrs::language`).

**Translation card**: the card between the event card and the message, saying what language the message is in and where its words would go to be translated. Once there is a translation it names what the message came from, and its button turns the message back to what arrived and forward again, which costs no second request. `mailrs::ui::translation::TranslationCard`. It appears only while the words read as a language the interface is not in, so a reader who gets mail in two languages meets it on half of it and never on the rest. _Avoid_: banner, translate bar.

**Release**: a version published on GitHub from a `vX.Y.Z` tag, with a .deb, a tarball, a zip, `SHA256SUMS`, and its section of `CHANGELOG.md`. `scripts/release.sh` makes the tag and the release workflow builds the rest. `mailrs::update::version::Release` is what the app reads of one. _Avoid_: build, version (for the published thing).

**Update**: installing a newer release over the running copy, the way that copy was installed: apt behind a password prompt for the .deb under `/usr`, the tarball's own `install-files.sh` for a copy under the person's home. The app then restarts into it in place. A copy run from a cargo build or as the demo never updates. `mailrs::update`. _Avoid_: upgrade, patch.

**Newsletter**: a sender whose mail carries a `List-Unsubscribe` header, or an unsubscribe link in its body. `mailrs_store::newsletters::list` groups the last 90 days of an account's mail by sender address to find them, so the assistant can be asked what the person is on and leave several at once. Gmail's Promotions, Updates and Forums categories catch the rest: a sender whose header the store has not kept still counts, and `mailrs_sync::Newsletters::list` fetches the header for the ones that write often enough to be worth a call. _Avoid_: mailing list, bulk sender, subscription.

**Way out**: how one newsletter lets go, in the order Penguin Mail tries them: the header's one-click POST, the header's web page, the header's `mailto:`, then a link in the body when the header offers none. `mailrs_sync::unsubscribe::Unsubscribe`, picked by `choose_with_body`. A page comes before a mail request because a mail request often does nothing and a page is what works. A body link comes last because it is whatever the sender made it. The one-click POST goes to the list's own server through `mailrs_sync::OneClick`, never through the account's provider; tests and the demo post to `FakeOneClick`. _Avoid_: unsubscribe method, opt-out channel.

**Left list**: a newsletter the person unsubscribed from, kept by the sender's lower-case address with how it was left (`one_click`, `page` or `email`) and when. `mailrs_store::unsubscribes`, written through `mailrs_sync::MailActions::left` by the window and the assistant once a list let go, never for a request still in the Outbox. A conversation from a left list opens with no Unsubscribe banner, and `list_newsletters` marks the sender as left. _Avoid_: unsubscription, opt-out record.

**Unsubscribe page**: the page a way out leads to, loaded out of sight and read as data. `mailrs::unsubscribe_page::PageForm` is its address, its title, its visible text and the fields and buttons of its forms, with no markup in it, so neither the rules nor a model see what the sender wrote. `pick` answers a `Plan`, which names by id the fields to fill, the boxes to tick and the button to press, or says it is unsure and the page opens in the person's browser instead. `prepare` reads and decides, the person says yes, `finish` submits. The only text it ever types into a page is the address the newsletter was sent to. _Avoid_: preference centre, opt-out form, landing page.

**Packaging**: the kind of package a build is for: native (the .deb, the tarball and a build from source), rpm, Flatpak or Snap, chosen at build time with the cargo features `packaging-rpm`, `packaging-flatpak` and `packaging-snap`. `mailrs::packaging::BUILT_FOR`. It decides who installs new versions, dnf, Flathub or the Snap Store for their packages and the app itself for the rest, and whether skills run: a skill's sandbox cannot start inside the one Flatpak or a snap puts the app in, so both turn skills off. _Avoid_: distribution, flavour, channel.

**Release key**: the OpenPGP key that signs the apt and dnf repositories and each release's `SHA256SUMS`, fingerprint `FE3C3B6E699AF939DC4670DCF3A853035C3E2B8E`. The app carries its public half, `mailrs::update::signature::RELEASE_KEY`, read from `packaging/apt/penguin-mail-archive-keyring.gpg` at build time, and trusts the sums of a release it installs only when `SHA256SUMS.asc` is a good signature by it. The release workflow reads the private half from the `APT_SIGNING_KEY` secret. _Avoid_: signing key, archive key, GPG key.

**Backend error**: what went wrong on a mail server's side, as a kind every provider shares: the account needs to sign in again, the network is down, the server is rate limiting, something is not found, the server lost its place, a permission is missing, the server refused, or it cannot do that at all. `mailrs_sync::BackendError`, carried as `SyncError::Backend`. The retry rules and the account states read the kind. What only Gmail can say, such as an API switched off in the Cloud project, stays in its `Gmail` variant, and a kind that stands for a Gmail error keeps Gmail's wording. _Avoid_: Gmail error (outside the Google adapter), API error.

**Service**: one kind of work an account can be asked for: mail, calendar, contacts, rules, the automatic reply, or the addresses it sends as. Each is a trait in `mailrs_sync::services` (`MailBackend`, `CalendarService`, `ContactsService`, `RulesService`, `AutoReplyService`, `IdentityService`), and a provider's adapter implements the ones it offers. `services::Google` is the only adapter; it works over any `GmailApi`, the real client or `FakeGmail`, maps Gmail's errors to backend errors, and keeps Gmail's quota to itself. `IdentityService` answers send-as addresses and has nothing to do with the composer's identity. _Avoid_: API, backend (for anything but mail).

**Capability**: a fact about what an account's mail service can do: whether a message can sit in several server mailboxes, whether the server keeps threads, files its own sent mail, sorts the inbox into categories, and can erase mail for good; which keywords it stores; whether it reads a search in its own syntax; and the most messages one write may name. `mailrs_sync::MailCapabilities`, from `MailBackend::capabilities`. Gmail has all of them, stores `$seen`, `$flagged` and `$muted`, reads Gmail's search syntax, and takes a thousand messages a write. `ops_for` reads the first to choose between filing and moving. The window and the assistant read capabilities through `Offers`. _Avoid_: feature, support flag.

**Account services**: the services one account is served by, one closed enum per kind of work (`AnyMail`, `AnyCalendar`, `AnyContacts`, `AnyRules`, `AnyAutoReply`, `AnyIdentities`) with a variant for each adapter, so every call is a `match` and nothing is boxed. `mailrs_sync::AccountServices`, built by `AccountServices::google` for a signed-in account, which `connect` picks by the account's **provider**, and `AccountServices::fake` for tests and the demo. A service the provider lacks is `None`, and the module that needs it answers `BackendError::Unsupported`; the calendar, contacts, rules and the automatic reply are optional this way. _Avoid_: client, API, backend.

**Offers**: what one account can do, read from its services for the window and the assistant: whether mail takes labels or moves between folders, whether the inbox has categories, whether mail can be erased for good, whether the account has a calendar, contacts, rules and an automatic reply, and whether its server searches past the mail on this computer. `mailrs_sync::Offers`; `Missing` names one thing it lacks, and `mailrs::offered::reason` says why in a line worded for the provider. An account that has not started offers everything until it does. _Avoid_: features, permissions (a permission is what the person grants).

**Filing**: how the accounts in question file mail, and so the words the window uses for it: with labels, several on one message, or in folders, one per message. It is folders only when every account in question files in folders. Labels, Move to Folder, New Label or New Folder, and the Rename and Delete dialogs follow it; deleting a label leaves its mail, while deleting a folder deletes the mail in it. Mail from several accounts takes a label by name only when every one of them files with labels (`Filing::across`). On a folder account every action that puts mail somewhere moves it there, a drop from Flagged or a search included, and mail that leaves a folder with nowhere named goes to the Archive; two folders at once is refused. The Labels button and the Keyboard Shortcuts window follow it too: the button reads as its picker does, by the mailbox's accounts with nothing picked and by `Filing::across` for mail from several accounts (`Filing::picker`). `mailrs::offered::Filing`. _Avoid_: label mode, folder mode.

**Move to Folder**: what the Labels button and menu item become on an account that files in folders: choosing a folder moves the mail there instead of adding a label, which on that server would leave a copy behind. It runs `TriageAction::MoveTo` with the folder's id, which `ops_for` turns into `MailOp::MoveToMailbox` on a folder server, and into filing in the mailbox and leaving the inbox on Gmail, as Gmail's own Move to does. The assistant's label tool does the same when an account files in folders and it is given one folder to add. _Avoid_: file, copy to folder.

**Provider**: the company or protocol serving an account's mail: Gmail, or IMAP for any other server. `mailrs_domain::Provider`, kept in `accounts.provider`; it picks which adapter serves the account. An IMAP account also keeps who runs its server as the person knows them, such as Fastmail, in `accounts.provider_name`, and its two servers in `account_servers`; `Account::provider_name` gives that name, or "Gmail". _Avoid_: backend, service (which is a kind of work).

**App password**: a password a provider makes for one app from a page in the account's settings, used in place of the account's own password. Some providers, such as Fastmail and iCloud, always want one for IMAP; others only once two-step sign-in is on. The provider table says which, with the page that makes one, and Add Account says so under the password field and again when a login is refused. Penguin Mail keeps it in the keyring under `penguin-mail-imap`, keyed by the account's id, and never in the store. `mailrs_discover::PasswordKind`, `mailrs_sync::passwords`. _Avoid_: token, app-specific password.

**Server mailbox**: a place a server files mail in: a Gmail label, later an IMAP or Outlook folder. It has the server's id, a name, a kind (system, label, folder, or group: a folder that holds only other folders and no mail, as an IMAP server lists a `\Noselect` parent), sometimes a role, and a colour. `mailrs_domain::RemoteMailbox`, kept in the `mailboxes` table under an integer key. Not the sidebar's **Mailbox**, which may list a server mailbox, a search or a flag colour. _Avoid_: folder (which is Archive, Junk, Trash or All Mail), label outside Gmail's own words.

**Role**: what a server mailbox is for, whatever the server calls it: inbox, sent, drafts, trash, junk, archive, all or important. `mailrs_domain::Role`. Gmail's `INBOX`, `SENT`, `DRAFT`, `TRASH`, `SPAM` and `IMPORTANT` carry the roles; Gmail has no archive or all mailbox. Starred mail is a keyword, not a role. _Avoid_: special folder, system label (outside Gmail's own words).

**Keyword**: a mark a message carries that is not a place: `$seen`, `$flagged`, `$answered`, `$draft`, `$muted`, or any keyword a server stores. `mailrs_domain::mailbox::keyword`, kept in `message_keywords`. Gmail's `STARRED` and `MUTE` labels stand for `$flagged` and `$muted`, and its `UNREAD` label for the absence of `$seen`, so unread is kept as a fact derived from the keywords rather than as a row. _Avoid_: flag (which is the flag colour), tag.

**Membership**: one thing a message is in or carries: a server mailbox, a keyword or a category. `mailrs_domain::Membership`; everything one message holds is `Memberships`. A `MessageMeta` carries its memberships in `held` and the roles of its mailboxes in `roles`. `mailrs_gmail::labels` turns Gmail's labels into memberships and back. _Avoid_: label (outside Gmail), placement.

**Mail set**: which stored mail a list draws from: the mailbox with a role in each account (the inboxes), one server mailbox, the mail carrying a keyword (flagged, muted), unread mail, or one inbox category. `mailrs_domain::MailSet`. Thread lists, the sidebar's counts, triage and the rules name mail this way; only the Gmail adapter turns one into a label id. _Avoid_: label, filter, selector.

**Query tree**: a search in words every provider shares: sender, recipient, subject, words, a day range, days back from now, size, an attachment, unread, flagged, a mail set, or a mailbox by the name a person typed, joined by And, Or and Not. `mailrs_domain::query::Query`. Folders and smart mailboxes are query trees. The Gmail adapter prints one as Gmail search text with `mailrs_gmail::query::print`, `mailrs_domain::query::describe` prints one in plain English words for an account that reads no search syntax of its own, and the store runs one over its own copy of the mail with `mailrs_store::query::matching`, for a server that reads no Gmail syntax. What a person types into the search box stays in Gmail's operators (`SearchQuery::Native`); a Gmail account reads that text as it stands, and `mailrs_domain::query::parse` reads it as a tree for any other account. _Avoid_: filter, search string.

**Change set**: the one way stored mail changes: a list of changes (store a message, keep it under a new sync generation, add it to or take it out of a server mailbox, set a keyword or a category, delete a message or a thread, mark a thread whole) applied in one call inside the caller's transaction. It refreshes every thread row the changes touched and reports what each membership change did to each message, which is what Undo reverses. `mailrs_store::messages::apply`, taking `Change`s and answering `Touched`. _Avoid_: update, patch (which is the conversation page's word), batch.

**Listed**: whether a list shows a thread, kept on the thread's rows rather than worked out per query. A thread is listed in a server mailbox while one of its messages there sits outside the Trash and Spam (the mailbox itself aside, so the Trash lists trashed mail), and listed at all while any message of it sits outside both. `thread_mailboxes.listed`, `thread_categories.listed` and `threads.listed`, derived by the change set. The counts read the same rows, so a count and its list agree. _Avoid_: visible, hidden (for the column).

**Mail operation**: one change an action makes to messages, in words every server shares: file in a server mailbox, take out of one, move to the mailbox with a role, set a keyword or a category, or erase. `mailrs_sync::MailOp`. `ops_for` turns a triage action into operations for the account's capabilities (Archive on Gmail takes the inbox off; on a folder server it moves to the archive), the store applies them through the change set, and the backend sends them: the Google adapter as label changes, batched. _Avoid_: label delta, command.

**Sync state**: where an account's mail backend left its feed of changes, in the backend's own words, kept as text in `accounts.sync_state` and read only by the adapter that wrote it. Gmail's is `{"history_id":N}`. `MailBackend::changes` takes one and answers what changed since, as gains and losses of memberships, with the state after; with none it answers where the feed stands now. A state the server no longer keeps, or cannot read, is `StateLost`, and the engine lists the mail again. `mailrs_sync::SyncState`. _Avoid_: cursor (which is also the backfill page token), history id (outside the Google adapter).

**Remote ref**: what the server calls a message now: Gmail's message id, or an IMAP location, the mailbox, its UIDVALIDITY and the UID (`mailrs_domain::Location`, written `<mailbox>/<uidvalidity>/<uid>`). The store keeps each message's in `remote_refs`, apart from its own id. An IMAP message's id is the location where the app first met it; a move rewrites the ref and leaves the id, so reminders, flags, the cached body and the open conversation keep their message. The engine hands the adapter each message's remote ref and reads the adapter's answers back into store ids (`mailrs_store::remote_refs`). A stored id whose ref now names another place is stale, and news naming it is dropped. For Gmail the two are the same and the engine reads no refs. Listings and searches answer them as `mailrs_sync::RemoteRef`. _Avoid_: server id, handle.

**Provider table**: the mail providers Penguin Mail knows without asking anyone: for each, its display name, its address domains, the MX hosts that mark a custom domain it hosts, its IMAP and SMTP servers, which password it takes, and the pages that make an app password and turn IMAP on. It also names the providers the app cannot reach over IMAP (Tuta and HEY, and Proton Mail for now) and the domains that belong to the Google or Microsoft sign-in. Compiled in from `discover/providers.toml`; `mailrs_discover`'s `table::Table`. _Avoid_: ISPDB (which is Mozilla's database, and only ever asked over the network), provider list.

**Discovery**: finding the mail servers for an address the person typed. The provider table answers by the exact domain with no network; otherwise the MX match, the domain's own autoconfig file, Mozilla's ISPDB, the MX host's settings, SRV records and a probe run side by side, and the highest-priority step that found something wins, each step dropped after 10 seconds. Only the address's domain goes out, and no name above it is ever built. `mailrs_discover::find`, answering a `Found`: a verdict and candidate servers, each marked with where it came from and whether the person must confirm its host names. _Avoid_: autodetect, autoconfig (which is one of its steps), Autodiscover (Microsoft's, which it never calls).

**IDLE connection**: the one IMAP connection per account that waits in IDLE (RFC 2177) on the mailbox the caller names, usually the Inbox, so the server reports new mail there as it arrives; a server without IDLE gets no such connection. The adapter ends the IDLE and issues it again every 25 minutes, and the engine keeps one watch across its polls. At most two more connections run sync and actions. `mailrs_imap::ImapClient::idle`. `MailBackend::watch` ends when the server reports a change, which wakes the engine's loop at once. A server that sends more during IDLE than the client takes loses the connection (`Woke::Dropped`); the engine syncs, and the next IDLE waits a minute, doubling at each drop in a row up to 15 minutes. Other mailboxes wait for the slow poll: every 5 minutes with the window open, every 15 with only the tray. A server without IDLE has its Inbox polled every minute. _Avoid_: push connection, listener.
